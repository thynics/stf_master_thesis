\chapter{Results}
\label{chap:results}

This chapter evaluates the proposed CUDASTF runtime scheduler using a set of
controlled placement and DVFS experiments. The evaluation is organized around
the research questions introduced in Chapter~\ref{chap:methods}: whether a
HEFT-relative placement policy can improve locality without sacrificing the
stability of HEFT, whether the observed speedups can be attributed to concrete
data-movement behavior, and whether a guarded window-level DVFS controller
can reduce energy while keeping latency overhead small.

The chapter deliberately separates placement evidence from DVFS evidence. In
the placement experiments, DVFS is disabled and the comparison is between HEFT
and the bandit scheduler. In the DVFS experiments, the placement
framework is held fixed and the comparison is between a no-DVFS baseline and
WinDVFS. This separation makes the results easier to interpret:
placement changes where a task executes, while DVFS changes the frequency at
which the selected GPU runs.

The main placement result is that the bandit scheduler improves
geometric-mean kernel latency by \(7.146\%\) across six benchmarks when the
mean of each five-run benchmark batch is used. The strongest placement gains
occur on CG, Cholesky, and LU decomposition, and
the locality analysis shows that these gains coincide with large reductions in
copy traffic. The main DVFS result is that WinDVFS reduces
geometric-mean kernel energy by \(2.904\%\) with a geometric-mean kernel
latency overhead of \(0.626\%\). The DVFS effect is therefore useful but
workload dependent: four benchmarks show clear kernel-energy reductions, one
benchmark shows a smaller energy reduction with a visible latency trade-off,
and one benchmark remains near neutral.

\section{Experimental Protocol}
\label{sec:results-protocol}

All final experiments target single-node, eight-GPU CUDASTF execution. The
application-visible GPU set contains eight GPUs, and every row used in the
final tables sampled all eight allocated devices. Each benchmark row is
launched as a fresh process so that CUDA context state, scheduler state, and
DVFS state do not intentionally carry over between measured rows.

The evaluation uses six CUDASTF benchmarks: FDTD, CG,
MiniWeather, Cholesky, LU decomposition, and
Blocked N-body. Table~\ref{tab:results-public-protocol} summarizes
the public experimental structure. The table reports what each experiment is
intended to establish, the number of measured repetitions used for the main
rows, and whether DVFS is enabled.

Kernel latency is the primary performance metric throughout the chapter. For
DVFS, kernel energy is the primary energy metric because it integrates NVML
power samples over the benchmark kernel window. Whole-process energy is useful
as auxiliary context, but it is not used for the headline DVFS decisions in
this chapter.

\section{Measurement Validation}
\label{sec:results-measurement-validation}

Before using the benchmark data for placement or DVFS conclusions, the
measurement setup was validated on all six benchmarks. This validation checks
that both HEFT and the bandit scheduler execute successfully with DVFS
disabled, that kernel timestamps are present, that NVML kernel-energy samples
are available, and that every row uses the intended eight-GPU configuration.

The validation run already shows the qualitative behavior expected from the
placement scheduler: CG, Cholesky, and
LU decomposition improve substantially, whereas
MiniWeather and Blocked N-body remain almost unchanged.
Because this validation uses only one measured run per row, it is not used as
the final performance evidence. The placement conclusions below use repeated
benchmark batches.

\section{Placement Performance}
\label{sec:results-placement-performance}

The main placement experiment compares HEFT against
the bandit scheduler with DVFS disabled. The six benchmarks are measured
in five-run batches. Since frequency control is disabled, the latency
differences in this section are attributed to placement and scheduling
behavior rather than to clock changes.

Using the mean latency for each benchmark, the bandit scheduler obtains
a six-benchmark geometric-mean speedup of \(1.076965\times\), equivalent to a
normalized runtime reduction of \(7.146\%\) relative to HEFT. Using medians,
the geometric-mean speedup is \(1.063759\times\), equivalent to a normalized
runtime reduction of \(5.994\%\). Table~\ref{tab:results-placement-main}
summarizes the per-benchmark results.

with an improved mean but worse median; and MiniWeather and
Blocked N-body remain close to neutral. This behavior is consistent
with the method design: the scheduler is a HEFT-relative residual policy, not
an unconstrained learned placement rule.

\section{Locality Attribution}
\label{sec:results-locality-attribution}

The locality-attribution experiment explains the placement result by measuring
copy traffic and non-HEFT deviation rate. DVFS remains disabled. The central
question is whether the speedups in Table~\ref{tab:results-placement-main}
correspond to measurable locality improvements rather than accidental runtime
variation.

Table~\ref{tab:results-locality-attribution} shows that the largest latency
improvements align with copy-byte reductions. Cholesky reduces median
latency by \(9.269\%\) while reducing copy bytes by \(38.220\%\), and
LU decomposition reduces median latency by \(15.891\%\) while
reducing copy bytes by \(23.905\%\). FDTD shows a smaller but still
consistent locality improvement. By contrast, MiniWeather and
Blocked N-body have zero deviation rate and zero copy-byte reduction,
which explains their near-neutral latency behavior.

\begin{table}[t]
\centering
\small
\begin{tabular}{@{}lrrr@{}}
\toprule

\midrule

Cholesky & \(-9.269\%\) & \(-38.220\%\) & 0.281154 \\

These results support the intended placement behavior. When the runtime
observes a non-HEFT placement that can reduce copy traffic while keeping the
predicted finish-time penalty bounded, the residual gate accepts the
deviation. When no such opportunity exists, the scheduler naturally collapses
back to HEFT-like behavior. This explains both the strong improvements and the neutral
controls without requiring a separate benchmark-specific policy.

\section{Robustness of the Placement Configuration}
\label{sec:results-placement-sensitivity}

The placement result should not depend on a single lucky run or on a narrowly
chosen control setting. To check this, the default placement configuration was
evaluated against nearby scheduler settings that change the adaptation window
and gate-selection bias. These checks were run with DVFS disabled and used the
same benchmark methodology as the placement experiments above.

The default configuration remained the strongest aggregate choice across the
robustness check, with a four-benchmark geometric-mean speedup of
\(1.076371\times\) relative to HEFT. It also preserved the qualitative
pattern observed in the main placement results: neutral workloads remained
close to HEFT, while the stronger linear-algebra workloads continued to show
large gains. The robustness check therefore supports using the default
bandit-scheduler configuration as the thesis configuration.

\label{sec:results-dvfs-energy}

The final DVFS experiment evaluates WinDVFS. Unlike the placement
experiments above, DVFS is enabled in the WinDVFS rows. The
comparison is against a no-DVFS baseline, and the primary metric is kernel
energy. The result should therefore be read as an energy-control result, not
as additional placement evidence.

table. FDTD, MiniWeather, CG, and

Blocked N-body is near neutral, which is consistent with the

\section{Threats to Validity}
\label{sec:results-threats}

The placement results are measured on a single eight-GPU node and may vary with
GPU topology, interconnect bandwidth, CUDA driver behavior, and benchmark
scale. The placement evaluation uses repeated runs, but some benchmarks still
show noise. FDTD is the clearest example: the mean and median results
point in different directions because the per-run order contains mixed
outcomes. The thesis therefore treats FDTD as a fragile or modest
locality case rather than as a headline placement improvement.

The locality attribution uses runtime copy metrics as supporting evidence.
Copy-byte reductions explain the observed improvements well for
Cholesky and LU decomposition, but they do not capture every
possible source of runtime variation, such as queueing effects, kernel launch
overheads, or overlap between computation and communication. The claim is
therefore consistent with the measured data movement rather than a complete causal decomposition of all
runtime effects.

The DVFS conclusion is based on kernel-window energy and kernel-window latency.
This is the right metric for the energy-control question studied here, but it
does not replace a full-system power study. The final DVFS rows show a
consistent aggregate energy reduction with small aggregate latency overhead,
yet larger run counts and additional hardware platforms would be needed before
claiming universal behavior. The diagnostic overhead results also show that
instrumentation and compact DVFS control are not free, so final timing and
energy claims should rely on the validation rows rather than on
instrumentation-heavy diagnostic rows.

\section{Results Summary}
\label{sec:results-summary}

The experimental evidence supports both layers of the proposed design. For
placement, the bandit scheduler improves geometric-mean kernel latency
by \(7.146\%\) using mean latencies across six benchmarks, while the locality
analysis shows that the largest improvements coincide with large copy-byte
reductions. The neutral controls show the complementary behavior: when no
copy-saving opportunity is present, the scheduler stays close to HEFT rather
than forcing arbitrary deviations. The sensitivity analysis confirms that the
selected default configuration is the best cross-workload choice among the
tested alternatives.

For DVFS, WinDVFS reduces geometric-mean kernel energy by
\(2.904\%\) with \(0.626\%\) geometric-mean kernel-latency overhead. The
clock and power evidence shows that the largest energy reductions are associated with
lower kernel average power and, in most cases, visible exposure to lower SM
clock levels. The final result is therefore not a universal claim that every
benchmark benefits from DVFS. Instead, it is a controlled result showing that a
guarded proposal--commit DVFS layer can extract energy savings from several
CUDASTF workloads while keeping the aggregate latency cost small and leaving
low-opportunity workloads near the baseline.
